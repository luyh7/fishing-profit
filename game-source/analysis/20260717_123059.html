20260717_123059 游戏源码与利润网逻辑对照

结论

利润网与该版本游戏源码不完全一致。地图、鱼种、基础鱼价、付费鱼饵、基础速度和稀有度倍率等静态数据整体可靠，但高渔力概率、S1 UTR、星空图 UTR、幸运药水、24 小时完成次数、展示木框及若干猫猫乐园细节会直接改变利润结果。

本报告以游戏实际结算路径 core/engine.py 为优先依据；若源码的展示函数、注释或文档与实际抽取代码冲突，会单独标注源码内部不一致。

已确认一致

  1. 21 张地图的 ID、名称、难度和鱼池顺序一致，共 110 个鱼种配置。利润网见 config.js，源码见 locations.json 和 fish.json。

  2. 110 个鱼种的 N 基础价逐项一致。

  3. 6 种付费鱼饵的 ID、名称、价格、速度一致；网页的小数速度与源码百分数只是单位不同。

  4. 鱼钩 Lv.1-Lv.10 均为每级增加 10% 速度，基础鱼竿等级 0-20 一致。

  5. N/R/SR/SSR/UR/UTR 价格倍率 1/2/4/8/16/32 一致。

  6. 基础间隔、鱼钩、鱼饵及打窝、周末、雨天、猫猫乐园独立速度乘区的组合方式一致。网页见 app.js，源码见 config.py 和 core/speed.py。

  7. 普通概率表在渔力差 d=0-8 时一致。

  8. 雨天 +10% 速度、暴雨 50% 节省鱼饵、流星天气把 2 个百分点从次高档移到最高档的基础规则一致。

  9. 猫猫乐园 9 栋建筑的顺序及累计数值一致，包括材料率 30%-45%、鱼饵节省/速度/鱼价/天气/双倍鱼获 3%/6%/10%、鱼竿等级 +1 概率 5%/15%/30% 和竣工材料价 80。

  10. 自动模式下，迷途风需要玩家完成当前地图 collect_scene_<id> 成就才生效，这一点一致。网页见 app.js，源码见 models/buff.py。

  11. 幸运药水在猫猫乐园未竣工时优先材料、竣工后优先非材料的大方向一致。

高影响差异

1. 高渔力概率与 S1 UTR 错误

游戏概率表有 d=0-19 共 20 行，超范围时钳制到最后一行，见 constants.py 和 constants.py。利润网只正确覆盖较低差值，并把 d=12-21 全部写成 0，见 config.js。随后网页会把这些地图判为“暂无数据”，见 app.js。

例如鱼竿 Lv.20 时，地图 1-9 及 S1 都会在利润网中因 d>=12 失效，但游戏仍会正常抽取。

S1 的最大稀有度是 UTR，见 locations.json。利润网没有保存每张地图的最大稀有度，而是把 d=9-11 的 UTR 概率统一并入 UR。以 S1、鱼竿 Lv.15、d=9 为例：

  • 游戏：SR 6.77% / SSR 37.74% / UR 44.12% / UTR 11.37%。

  • 利润网：SR 6.77% / SSR 37.74% / UR 55.49% / UTR 0%。

  • 不计材料和其他 buff 时，稀有度期望倍率从游戏的 13.9876 降为网页的 12.1684，鱼价期望低估约 13.01%。

2. 11-20 星空图成就解锁后的常驻 UTR 被漏算

游戏的 11-20 图在完成当前图 N-UR 全收集后，不依赖迷途风，常驻使用递进 UTR 概率和 150 次保底。实际入口见 core/engine.py 和 core/engine.py。

利润网只在天气类型为 lost_wind 时加入 UTR，见 app.js。而星空图源码明确不生成迷途风，只生成太阳风、流星雨或恒纪元，见 weather_service.py。因此已解锁玩家在 11-20 图的 UTR 收益被完全漏算。

3. 幸运药水的取优标准不同

游戏优先级是“展示木框 > 迷途风 UTR > 普通鱼稀有度”，同稀有度时还可能优先未收集鱼种，并不比较鱼的实际售价，见 core/engine.py 和 core/engine.py。

利润网按实际鱼价选更贵的鱼，见 catch-outcome.js。现有测试也把这条不同规则固化为预期，见 tests/catch-outcome.test.js。这会高估同稀有度内高价鱼被选中的概率。

4. 幸运药水与 UTR 保底的组合顺序不同

游戏先检查共享的 150 次保底；未触发保底时才做 1-2 次随机判定，最后只按一次最终结果更新保底计数，见 core/engine.py 和 core/engine.py。

利润网先把单次 UTR 基础概率折算成长周期“有效概率”，再对这个已含保底的分布做两次取优，见 app.js 和 app.js。这等价于让两次判定各自携带一套保底，数学上不一致。

仅以基础 UTR 0.2%、忽略木框和材料为例：

  • 按游戏顺序，幸运药水长期 UTR 约为 0.8850%。

  • 按利润网顺序，结果约为 1.5361%。

  • 利润网相对高估约 73.56%。

5. 24 小时完成次数少算末尾概率鱼获

游戏先结算完整间隔，剩余不足一个间隔的时间再按 剩余时间 / 间隔 做一次 Bernoulli 判定，见 core/engine.py 和 core/engine.py。因此固定时长内的期望次数等于理论次数，而不是理论次数向下取整。

利润网用 floor(24 / interval) 同时计算总收入和鱼饵成本，见 app.js。结果最多少计不足 1 次鱼获和对应成本；在低速配置下相对误差更明显。

6. 展示木框掉落与保底完全未建模

非星空图每次有 0.7% 概率先掉展示木框，并有 150 次保底；木框会替代该次鱼获，见 core/engine.py 和 core/engine.py。木框可按 100 金币出售，见 backpack/sell.py。

利润网的结果分布只有鱼和猫猫乐园材料，见 catch-outcome.js，因此既把木框发生时当成鱼，又没有计入木框价值。无其他机制时，0.7% 随机率加 150 保底的长期木框率约为 1.0747%；净误差方向取决于该图鱼价及是否把木框按出售价值计价。

7. 多多药水与旋转逗猫棒组合倍率错误

游戏把多多的整数倍数与逗猫棒概率相加：2 + double_rate，见 core/engine.py。利润网按乘法计算：2 * (1 + double_rate)，见 app.js。

逗猫棒 Lv.3 时，游戏期望数量为 2.10，网页为 2.20，鱼获收入部分高估约 4.76%。此外，游戏会按实际多倍数量推进展示木框和 UTR 保底计数，见 core/engine.py，网页固定按 150 次换算，没有体现多多对保底进度的加速。

8. 猫猫乐园鱼价取整顺序错误

游戏先算完整稀有度价格，再乘建筑加成并向下取整：int(base * rarityMultiplier * (1 + bonus))，见 cat_park.py。利润网先对加成后的 N 价四舍五入，再乘稀有度倍率，见 app.js。

例如 N 价 47、UR、鱼价 +10% 时，游戏价格为 floor(47*16*1.1)=827，利润网为 round(47*1.1)*16=832。

其他功能性差异

  1. 利润网缺少鱼钩 Lv.0。源码新玩家默认 Lv.0，网页自动同步时找不到选项，会继续按至少 Lv.1 的 +10% 速度计算。见 models/user.py 和 app.js。

  2. 利润网鱼竿选项止于 Lv.20；游戏在基础 Lv.20 上领取满级传奇猫雕像奖励后可达到有效 Lv.21。见 cat_park.py。

  3. 多多药水只在结算时令有效鱼竿 -1，不影响玩家已经满足的地图准入；网页却先减等级再过滤地图。见 core/actions.py、models/buff.py 和 app.js。

  4. 持票玩家进入 S1 不受鱼竿等级 6 限制，网页仍按难度过滤，见 core/actions.py。反方向上，11-20 图还要求星空艇，网页只检查鱼竿等级，可能推荐玩家尚不能进入的地图。

  5. 游戏支持无鱼饵模式，库存耗尽后速度回到 0、成本为 0；网页只计算 6 种付费鱼饵。见 core/engine.py 和 app.js。

  6. 状态 API 会返回许愿、加速、双倍捕获、幸运、多多和闪光等 buff，见 status_api.py；利润网只识别多多和幸运，其他有效 buff 会被当作“无药水”。其中加速和双倍捕获会直接改变利润。

  7. 11-20 图每次普通鱼获还会独立尝试掉落流星鱼，基础概率 5%，见 core/engine.py 和 constants.py。利润网没有折算流星鱼及太阳风/流星雨/恒纪元/闪光药水带来的额外奖励，因此当前结果不是星空图的完整综合收益。

  8. 第一条未收集的 UTR 会被游戏自动消耗以解锁图鉴，见 core/result.py。利润网把所有 UTR 都按可出售鱼计算；对未完成图鉴的玩家会高估短期可售收入，同时又没有计入一次性成就金币。

  9. 猫天气中，游戏当前实现只有结果真正进入 fish_caught 时才扣鱼饵；单条鱼完全被猫吃掉时不扣，见 core/engine.py。利润网仍对每个完成次数计成本。该行为可能是游戏源码 bug，但与当前执行代码不同。

  10. 猫天气金币礼物使用未加猫咖价格的原鱼售价并执行整数除法；利润网使用已加成的期望鱼价和浮点一半。源码见 core/cat.py，网页见 app.js。

  11. 猫送同稀有度鱼时，源码优先第一条未收集鱼，全部收集后才选最贵鱼；网页未完成成就时按整张图平均鱼价。源码见 core/cat.py。

  12. 幸运药水会对猫礼物额外判定一次猫猫框，可能用猫框覆盖首次金币/鱼饵/送鱼结果；利润网没有这一步，见 core/cat.py。

  13. 猫天气的猫猫框可出售 200 金币，但利润网明确按 0 收益处理。若“利润”定义为所有可出售物品的现金等价，这会低估收益；若只统计鱼币即时收入，则属于口径选择。

  14. 利润网页面允许手动构造源码升级规则不允许的猫猫乐园建筑组合，例如雕像等级不足时直接把其他建筑升到 Lv.2/Lv.3。源码限制见 cat_park.py。自动同步的真实玩家状态不受影响。

  15. 流星天气在高渔力差下的处理顺序不同。游戏先在完整原始概率槽位上搬移概率，再按地图最大稀有度封顶；网页直接在已经封顶的可见分布上搬移。普通图 d=9-10 时，游戏的 UR -> UTR 搬移最终仍封回 UR，鱼价分布不变；网页却会把 SSR 搬到 UR，虚增收益。源码见 constants.py，网页见 app.js。

  16. 游戏在 24 小时模拟的每个捕获时间点重新读取天气、药水和鱼饵库存，并会在当前鱼饵耗尽后换饵，最终进入无饵模式；网页把当前 buff 快照外推到完整 24 小时，并假定所选鱼饵无限供应。源码见 core/engine.py 和 core/engine.py。因此网页更接近“配置保持不变时的稳态方案比较”，不是玩家当前背包状态的逐时模拟。

源码自身的不一致

概率展示函数会把超过地图最大稀有度的高阶索引封顶合并，见 constants.py；实际抽取代码却把 index>=6 回退成 N，再执行字符串稀有度封顶，见 core/engine.py。

例如普通 UR 上限地图在 d=11 时：

  • 源码展示/利润网配置：SSR 10.85% / UR 89.15%。

  • 实际引擎：N 7.04% / SSR 10.85% / UR 82.11%。

因此修正利润网高差值概率前，需要先确认游戏作者希望对齐“展示意图”还是“当前实际抽取”；若以真实结算为准，应同时向游戏源码反馈该问题。
